# Itinerary Quality Evaluation v0.1.0 初始基线

## 1. 基线定位

这是行程规划质量评估完成“硬规则 + LLM Judge”两层评估后的第一份开发基线，用于定位当前 `ItineraryPlanningAgent` 的内容质量问题，并为后续优化提供前后对照。

本基线只评价行程内容，不评价意图路由、多 Agent 调度和记忆副作用；这些能力由独立的 System Evaluation 负责。

## 5. 当前主要问题

1. **时间表达缺少一致性检查**：活动时间框、描述中的交通历时和下一活动开始时间可能互相冲突。
2. **未查询的精确信息过多**：模型会直接给出具体车次、时刻、票价和预算，虽然部分使用“建议”措辞，但事实风险仍较高。
3. **商务目标偶尔被旅游内容稀释**：固定会议得到保留，但空余时段可能堆入过多景点。

因此，第一轮业务优化优先解决“时间路线一致性”，第二轮处理“实时事实与候选信息边界”，第三轮再校准商务与休闲的比例。

## 6. 结果边界

- 10 个案例用于开发诊断，不能代表所有企业差旅场景。
- LLM Judge 与规划 Agent 使用同一模型家族，存在自评偏差。
- 同一份标准行程曾在单独评审和批量评审中得到 67 与 73 分，说明临界案例存在小幅评分波动。
- 因此，69 分和 60% 是当前单次初始基线。正式对外表述优化效果前，应在相同数据集和配置下重复评审，并结合硬规则与人工抽查确认。

## 7. 基线结论

当前行程规划已经能够稳定满足明确的输入约束，但“满足要求”不等于“内容质量稳定”。初始基线显示，项目最需要优化的不是 Agent 是否被调用，而是生成结果内部的时间一致性与事实可靠性。

后续改动必须使用同一批已保存行程重新评分或使用同一数据集重新生成，并同时比较平均质量分、质量合格率、各维度得分和具体失败案例，避免只展示单个成功样例。
