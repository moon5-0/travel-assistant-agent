# RAG Retrieval Evaluation v0.2.0 混合检索优化

## 1. 本版本目标

纯向量基线在精确政策词、相近主题排序和跨知识块问题上存在召回不足。本版本没有为失败题增加答案映射或 Case 特判，而是实现通用的混合检索链路：

```text
用户问题
→ 静态知识库能力边界检查
→ BGE + Milvus 召回语义候选
→ 内存 BM25 召回关键词候选
→ RRF 融合两路排名
→ 语义安全门槛
→ 近重复过滤
→ 返回 Top-4 证据
```

## 2. 主要实现

### 2.1 双路候选召回

- 向量检索从 Milvus 召回 20 个候选，负责语义近似和改写表达；
- BM25 从 66 个知识块的内存索引召回 20 个候选，负责精确词项匹配；
- BM25 语料在首次检索时延迟加载并缓存，知识库写入新文档后自动使缓存失效。

### 2.2 RRF 排名融合

向量相似度和 BM25 分数的量纲不同，因此不直接相加，而是根据两路排名计算 Reciprocal Rank Fusion 分数：

```text
RRF(d) = Σ 1 / (60 + rank(d))
```

同时被语义检索和关键词检索排在前列的知识块会获得更高融合排名。

### 2.3 语义安全门槛

- 向量相似度不低于 0.50 的候选可以直接保留；
- 分数处于 0.43～0.50 时，必须同时被 BM25 召回；
- 低于 0.43 的候选即使有关键词重合也不进入最终结果。

该门槛用于防止 BM25 因“可以、什么、情况”等通用词，把编程问题或其他领域内容错误匹配到差旅知识库。

### 2.4 能力边界和近重复过滤

实时天气、余票、即时价格、库存和交通状态不属于静态政策知识库，检索前会识别这类动态信息需求并交由实时查询能力处理。候选输出阶段则通过文本归一化和字符序列相似度，过滤相似度不低于 0.92 的近重复知识块，避免重复证据占用 Top-K。

## 4. 优化结果

| 指标 | 纯向量基线 | 混合检索 | 变化 |
| --- | ---: | ---: | ---: |
| Evidence Recall@4 | 75.00% | **91.67%** | **+16.67 个百分点** |
| MRR@4 | 61.11% | **70.14%** | **+9.03 个百分点** |
| Evidence Precision@4 | 22.92% | **25.00%** | **+2.08 个百分点** |
| Negative Rejection Rate | 100% | **100%** | 保持不变 |
| 热检索 P50 | 12.91 ms | 13.34 ms | +0.43 ms |
| 热检索 P95 | 16.79 ms | 16.81 ms | +0.02 ms |
| 热检索平均延迟 | 12.34 ms | 11.93 ms | -0.41 ms |
| 执行异常 | 0 | 0 | 保持不变 |

混合检索找回了原先失败的私家车费用边界和平台跨知识块证据，12 道可回答题中有 11 道在 Top-4 内找齐证据。负例拒绝率仍为 100%，P95 延迟基本不变。

## 5. 剩余问题

当前仅剩 `hotel_minibar_reimbursement` 未命中。正确证据在向量候选中排第 20、BM25 候选中排第 15，具体规则被同一知识块内的报销流程等多个主题稀释。

本版本没有增加“迷你吧 → minibar”专用词表，也没有继续降低安全阈值刷到 100%。后续若继续优化，应优先将知识库改成按标题和规则项进行语义切块，再重新标注 Gold Evidence、重建 Milvus 并使用独立测试集验证。

## 6. 可对外使用的结论

> 针对纯向量检索在精确政策词和跨知识块问题上的召回不足，项目引入 BM25 关键词召回，并通过 RRF 融合语义与关键词排名，同时设置分层语义门槛控制误召回。在同一套 15 题 RAG 开发集和 66 个知识块上，Evidence Recall@4 从 75% 提升到 91.67%，MRR@4 从 61.11% 提升到 70.14%，负例拒绝率保持 100%，P95 热检索延迟基本不变。

该结论必须同时保留以下边界：

- 当前数据集是开发集，参与了方案选择，不是独立测试集；
- 数据规模为 15 题，只覆盖当前知识库中的主要差旅场景；
- 本阶段只评价证据检索，不代表最终 LLM 回答质量；
- 剩余细粒度政策失败需要通过语义切块等知识库设计继续解决。
