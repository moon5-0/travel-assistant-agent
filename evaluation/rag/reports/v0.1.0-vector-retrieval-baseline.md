# RAG Retrieval Evaluation v0.1.0 纯向量检索基线

## 1. 评估目的

在修改 RAG 检索设计前，使用固定开发集测量原有“BGE 向量化 + Milvus Lite 相似度检索”的实际表现，为后续优化提供同口径基线。

本次只评价检索器能否找到支持答案的知识块，不调用 LLM，也不评价最终回答措辞和 IntentionAgent 路由。

## 2. 评估配置

| 项目 | 配置 |
| --- | --- |
| 评估时间 | 2026-08-12 12:35（Asia/Shanghai） |
| 数据集 | `rag_dev_cases_v0.2.json` |
| 数据集版本 | `0.2.0-dev` |
| 数据规模 | 15 题：12 道可回答题、3 道负例 |
| 知识库 | `business_travel_knowledge` |
| 知识块数量 | 66 |
| 检索方式 | BGE 向量检索 + Milvus Lite |
| Embedding | `bge-small-zh-v1.5` |
| Top K | 4 |
| 相似度阈值 | 0.50 |
| 候选倍数 | 3 |
| 近重复阈值 | 0.92 |
| 原始报告 | `rag-retrieval-dev-v0.2-baseline.json`（本地生成，Git 忽略） |

所有可回答题均使用人工标注的 `source + chunk_index` 作为 Gold Evidence。只有父文档和知识块编号同时匹配才算正确召回。

| 指标 | 结果 |
| --- | ---: |
| Evidence Recall@4 | 75.00%（9/12） |
| MRR@4 | 61.11% |
| Evidence Precision@4 | 22.92% |
| Negative Rejection Rate | 100%（3/3） |
| 执行异常 | 0 |
| 热检索 P50 | 12.91 ms |
| 热检索 P95 | 16.79 ms |
| 热检索平均延迟 | 12.34 ms |

首次 Agent 启动耗时约 2.91 秒，检索预热耗时约 90.16 毫秒；两项不计入热检索延迟。

## 4. 失败分析

12 道可回答题中有 3 道没有在 Top-4 内找齐 Gold Evidence：

1. `hotel_minibar_reimbursement`：正确证据 `02_reimbursement_policy.txt#3` 未进入 Top-4。原始向量候选中该证据排第 20，相似度约 0.474，低于 0.50 阈值。具体个人消费规则埋在较长且主题混杂的知识块中，语义被稀释。
2. `private_car_reimbursement_boundary`：正确证据 `04_faq.txt#2` 排第 5，刚好落在 Top-4 之外。其他“费用、报销”相关知识块占据了前四名。
3. `platform_application_to_reimbursement`：问题需要 `06_platform_guide.txt#1` 和 `#2` 两个知识块。Top-4 只召回第一个，第二个排第 7，因此没有找齐完整证据。

这三类失败分别反映了原检索器对细粒度政策词、相近主题排序和跨知识块证据召回的不足。

## 5. 基线结论

原有纯向量检索能够保持 100% 的负例拒绝率和较低延迟，但 Evidence Recall@4 只有 75%，正确证据的平均排名也不够稳定。下一版本应在不牺牲负例安全性的前提下，引入关键词召回和排名融合，改善精确政策词与多证据问题。

本结果来自开发集，用于定位问题和指导优化，不等同于未参与调参的独立测试集成绩。
