# Agent Evaluation v0.1.0 未校准基线

## 1. 版本定位

这是差旅出行助手 Agent 评估链路第一次接入真实模型后的开发基线，用于验证评估系统能否发现问题，并为后续校准评分标准提供依据。

本报告属于**未校准开发基线**，不能将原始通过率直接表述为项目准确率，也不用于对外宣称生产效果。

| 指标 | 结果 |

| 场景运行数 | 5 |

当前采用严格评分：一轮中任一硬性检查失败，则该轮失败；一个场景中任一轮失败，则该次场景运行失败。

由于评分规则尚未校准，20% 同时包含真实业务失败、评分误判和规则漏检，不代表项目真实能力只有 20%。

## 5. 初步发现

### 5.1 项目行为问题

1. 普通行程规划可能过度调度 `PreferenceAgent`，增加延迟、费用和非授权记忆写入风险。
2. 行程规划可能生成未经实时工具验证的具体车次、时间、票价、天气和酒店价格。
3. 用户未说明行程目的时，事项收集 Agent 可能默认写入 `trip_purpose=旅游`。
4. 单独运行多轮场景时曾出现 IntentionAgent 非法 JSON；现有默认策略将其错误降级为 `information_query`。该问题在完整基线中未稳定复现，需要后续重复运行评估。

### 5.2 评估系统问题

1. `must_contain` 使用精确字符串，无法识别“没有”和“并未保存”等语义等价表达。
2. `pending_trip` 使用完整字典相等，可能将不影响核心状态的额外字段判为失败。
3. 偏好值使用字符串还是列表、`append` 与 `replace` 的业务合同尚未明确。
4. 未验证车次规则仅覆盖部分格式，未识别 `G112/G118` 等表达。
5. Trace 中的 `response` 是原始结果聚合文本，不完全等于 CLI 最终展示文本。
6. 数据集声明了参考日期，但 Agent 当前仍读取系统时间，相对日期评估不可完全复现。

## 6. 基线结论

v0.1.0 已证明评估链路可以完成以下工作：

- 在隔离记忆环境中运行真实多 Agent 场景；
- 保持同一场景内的多轮状态；
- 对调度、执行、实体、澄清、记忆和回复规则逐项评分；
- 保留失败轮次和原始 Trace，定位具体问题；
- 发现模型随机性、业务缺陷以及评分规则自身的误判和漏检。

本版本的核心成果是建立了可运行、可追踪的评估闭环，而不是得到可对外使用的最终准确率。

## 7. 下一步

1. 校准措辞、状态和偏好数据结构规则，减少误判。
2. 补全具体车次、价格、天气等安全规则，减少漏检。
3. 明确少量核心指标的计算口径，避免指标过多且难以解释。
4. 固定评估时钟，并在同一模型配置下重复运行场景。
5. 生成 v0.2.0 校准基线后，再开始修改业务 Agent，并进行前后对照。
