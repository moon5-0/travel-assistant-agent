# System Evaluation v0.4.0 优化后评估

## 1. 评估目的

在 v0.3.1 扩展基线之后，项目依次修复了结构化输出、缺失日期、多轮状态、长期记忆幂等、偏好结构、意图路由和无依据行程目的等问题。本次使用同一套 System Evaluation 数据集复测，用于衡量这些改动带来的实际收益。

本评估只检查系统行为，不评价最终行程内容质量。

## 5. 剩余失败

45 次运行中剩余 3 次失败，可归并为两类问题：

1. **待补全行程的续接路由不稳定（2 次）**：第一轮已经进入行程补全状态，第二轮用户只补充“从苏州出发”时，模型仅调度 `event_collection`，没有继续调度 `itinerary_planning`。协调器因此未执行待补全合并与缺失字段检查，错误返回 `completed`。
2. **明确复用历史时遗漏记忆查询（1 次）**：用户说“出发地和行程天数都按上次一样”时，模型没有调度 `memory_query`。最终实体虽然通过其他上下文被补全，但执行链路缺少显式、可追踪的历史读取步骤。

## 6. 结论与下一步

原基线中的五类主要失败已经基本消除，系统通过率从 75.6% 提升到 93.3%。下一轮只针对上述两项状态与路由问题增加确定性约束和离线测试，完成后再进行小范围真实模型复测。

System Evaluation 稳定后，项目进入独立的 Itinerary Quality Evaluation，开始评价行程内容是否合理，而不再只检查系统是否按正确流程运行。
